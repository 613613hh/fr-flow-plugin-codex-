# FineReport/Codex 异常处理协议

所有 FineReport 技能遇到异常时都遵循本协议。先分类，再执行安全的自动处理；无法安全推断时停止并报告，不要用猜测覆盖文件或数据库。

## 统一处理顺序

1. 记录失败命令、工作目录、退出码、关键错误行和当前阶段。
2. 判断是环境、路径、依赖、语法/构建、CPT 装配、数据库、运行时、QA 还是发布包问题。
3. 只执行与该类别对应的无破坏检查和修复；同一修复最多自动重试一次。
4. 修复后重新运行原检查。如果仍失败，停止当前阶段，不进入下一阶段。
5. 最终报告必须包含：原因、已执行的修复、仍未解决的问题、下一步需要用户提供的信息。

## 可自动处理的问题

### 环境和路径

- 缺少 `FR_WORKSPACE`、`FR_PROJECTS_DIR` 或 `FR_REPORTLETS`：先读取工作区 `.codex/env.json`、`.fr.yaml` 和当前目录推断；有多个候选路径时询问用户。
- 相对路径失效：转换为绝对路径后再次检查，不修改用户配置。
- FineReport 服务不可达：检查 URL、端口和服务进程；不要反复请求超过 2 次。
- 数据库连接失败：检查主机、端口、数据库名和用户是否存在；密码缺失或疑似错误时停止，不打印密码。

### 依赖

- 缺少 Python 包：优先使用项目已有虚拟环境或锁定文件；安装新包前说明包名和原因。
- 缺少 Node 依赖：优先执行项目已有 lockfile 对应的安装命令；不要删除 lockfile 或升级大版本。
- Playwright 浏览器缺失：提示安装目标浏览器，安装失败时保留原错误并停止 QA，不伪造通过结果。

### JSX、MJS 和 CPT

- JSX 语法错误：定位到文件和行号，修复源 JSX 后重新构建；禁止直接改 MJS 或 CPT。
- MJS 构建失败：检查 JSX 语法、构建参数和依赖；失败时不得覆盖原 CPT。
- CPT 装配失败：保留原 CPT，检查骨架文件、输出路径和编码；不得手工修改编译内容。
- CPT 已存在：先比较目标和源文件，确认是本次项目文件后再覆盖；无法确认时询问用户。

### 数据库和存储过程

- SQL 语法或执行失败：定位到脚本和语句；不得自动 DROP 生产对象或执行未授权的 destructive SQL。
- 存储过程变更不明确：询问是否属于本次变更；未确认时不把 SQL 放入 Release。
- SQL 文件缺失：如果本次声明有存储过程变更则停止发布；如果没有变更则省略 SQL。

### QA 和发布

- QA 失败：保存失败步骤和证据，回到对应的 JSX/数据层修复，不生成正式 Release。
- CPT 数量不等于用户指定数量：停止，不按目录全量打包。
- Release 包包含 JSX、MJS、备份或额外文件：删除暂存目录后重新按白名单打包。
- ZIP 校验失败：重新生成并检查 ZIP 清单；连续两次失败后停止。
- Git 工作区有无关修改：保留并报告，不执行 reset、checkout 或清理。

## 必须请求用户确认

- 修改或删除用户未明确指定的文件；
- 执行 DROP、TRUNCATE、DELETE 或生产数据库变更；
- 覆盖无法确认来源的 CPT；
- 推送远程仓库、创建正式 Tag 或发布内网包（除非用户当前请求已明确授权）；
- 需要新增外部依赖、访问新服务或扩大项目范围。

## 禁止行为

- 不把错误日志改写成“已通过”；
- 不跳过构建、CPT 校验或 QA；
- 不通过修改 MJS/CPT 绕过 JSX 语法错误；
- 不打印数据库密码、令牌或完整敏感配置；
- 不因一次偶发网络错误无限重试。
